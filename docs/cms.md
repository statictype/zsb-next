# CMS

Content is stored in Sanity. The Studio is embedded in this app at `/studio`, so a schema change, the GROQ query that reads it, and the component that renders it ship in one change.

## Content sources

| Content | Source |
|---|---|
| Editions, including their events, credits and press kit | `edition` documents |
| Artists, organizations, venues | `artist`, `organization`, `venue` documents |
| Event types, venue types | `eventType`, `venueType` documents |
| Press appearances and releases | `pressAppearance`, `pressRelease` documents |
| Homepage, About, Partners, Visit, Privacy, Press page | Singletons: `homepage`, `aboutPage`, `partnersPage`, `visitPage`, `privacyPage`, `pressPage` |
| Footer contact details and social links | Singleton `siteSettings` |
| `/galeria-beller` (Romanian landing page) | Singleton `galeriaBeller` |
| Artist profile works | `work` documents |
| Homepage editions list | Derived from `edition` documents and their `status` |
| Footer and navigation labels | Hard-coded in `Footer.tsx` and `Navigation.tsx` |

## Schema conventions

- Types are built with `defineType`, `defineField` and `defineArrayMember`; plain objects break TypeGen.
- Every document type has an icon from `@sanity/icons`.
- Validation lives in the field definition.
- Documents with more than six fields use field groups (see `edition`).
- `preview.select` and `prepare` make each list row identifiable without opening it.
- A field that is a list is an array, not a string split on a separator.
- Page body copy is an array of plain strings, rendered one `<p>` each. Only `privacyPage.body` is Portable Text, because it needs inline bold and links.

## Singletons

Sanity has no singleton option. Three guards enforce it, all driven by `SINGLETON_TYPES` in `src/sanity/lib/singleton.ts`:

1. `structure.ts` renders the document directly with `documentId === type`.
2. `document.actions` in `sanity.config.ts` removes delete, unpublish and duplicate.
3. `document.newDocumentOptions` in `sanity.config.ts` removes the type from the global "Create new" menu.

Query a singleton by id: `*[_id == "fooPage"][0]`.

A missing page singleton returns 404. Singletons are not created automatically, so a new dataset needs each one published in the Studio. Publish `siteSettings` first: the footer and the Partners page read `contactEmail` from it. Missing images inside an existing document resolve to `PLACEHOLDER_IMAGE` (`src/lib/placeholder.ts`).

## Fetching and draft mode

`draftMode()` and `cookies()` cannot be read inside `'use cache'`. Each page that can be previewed therefore has a dynamic half, which reads the request, and a cached half keyed on the result.

- `DraftAware` (`src/components/DraftAware/`) is the dynamic half. It resolves the fetch options, returns the published path without a Suspense boundary when draft mode is off, and renders the caller's cached leaf.
- `queryData(taggedQuery, options, params?)` in `live.ts` is the only caller of `sanityFetch`. It passes the perspective, sets `stega: false`, and stamps the query's `tags` on the cache entry. Call it from inside a `'use cache'` fetcher.
- `getDynamicFetchOptions()` resolves the perspective from draft mode and cookies. Call it outside `'use cache'`.
- `sanityFetchStaticParams()` is for `generateStaticParams` and always uses the published perspective. `sanityFetchMetadata()` is for `generateMetadata`, `sitemap.ts` and `opengraph-image.tsx`; it keeps the perspective and disables stega.

Singleton routes go through `singletonPage(key)` in `src/app/(site)/_lib/singleton-page.tsx`, which wraps a shared cached leaf in `DraftAware`, calls `notFound()` when `load` returns `null`, and exports `generateMetadata`. Dynamic routes such as `/editions/[year]` await `params` and wrap their own cached leaf in `DraftAware`. `EditionsNav` is embedded on several pages and wraps itself in `DraftAware`.

Route-level `loading.tsx` is not used on these routes. React places a Suspense fallback ahead of large content in the static HTML, so a route skeleton would paint before the prerendered page. The intercepted `@modal/(.)events/[slug]` route sets `export const instant = false` because its prerender has no concrete `year`.

### Stega

Stega encodes invisible characters into strings so Visual Editing can map text to fields. It is disabled for every fetch (`stega: false`), so metadata, JSON-LD and string comparisons need no cleaning. `<VisualEditing />` is not mounted; draft review happens in the Presentation tool, and mounting it would add about 269 KB gzipped (`@sanity/visual-editing` and `@sanity/ui`) to every public route.

## Live preview

The Presentation tool is configured in `sanity.config.ts` with the locations in `presentation.ts`. It enables draft mode through `/api/draft-mode/enable`. `DisableDraftMode` renders an "Exit preview" link while draft mode is on and calls `/api/draft-mode/disable`.

`<SanityLive />` is mounted in the `(site)` and `(beller)` layouts and not under `/studio`, where it causes reloads inside the Studio iframe. It refreshes open tabs when content they depend on changes.

## Caching and revalidation

`client.ts` uses the CDN and the `published` perspective. `next.config.ts` sets `cacheLife: { default: sanity }` from `next-sanity/live/cache-life`: a cache entry lives until a tag invalidates it, with no timer.

Each cached fetch carries two kinds of tag:

- Sync tags, added by `sanityFetch`, which `<SanityLive />` uses for open tabs.
- Type tags, from the `tags` array exported with each query in `queries.ts`. A query lists every document type it reads, including types reached through `->`. The webhook matches only these. A query missing a type tag is never invalidated by publishes of that type.

The webhook target `/api/revalidate/tag` verifies the signature with `SANITY_REVALIDATE_SECRET`, calls `revalidateTag(tag, { expire: 0 })` for each tag in the `{ tags: string[] }` body, then fetches `/`, `/visit`, `/editions`, `/galeria-beller` and, if an edition changed, each live edition page, so the next visitor gets a cache hit. It returns 401 for a bad signature and 400 for a missing `tags` array.

Configure the webhook at sanity.io/manage under API, Webhooks:

| Setting | Value |
|---|---|
| URL | `https://sculpturedays.com/api/revalidate/tag` |
| Filter | `_type in [...]` listing every document type in the schema; a type missing from the filter sends no webhook |
| Projection | `{ "tags": [_type, _type + ":" + _id] }` |
| Trigger on | Create, Update, Delete; drafts excluded |
| Secret | The value of `SANITY_REVALIDATE_SECRET` |

If a publish does not appear in production, check the webhook delivery log first. A 401 means the secret differs from the one in the hosting environment. Then check that the query's `tags` include the document type.

## Editions

`getEdition(year, options)` and `getEditionSummaries(options)` in `src/sanity/lib/editions.ts` are the gateway. The live-year list, the homepage list, archive cards, and the Latest and Upcoming derivation read the summaries. A new year is an `edition` document; no code change is needed.

Event URL slugs come from `deriveEventSlugs` in `editions-mappers.ts`. An editor-supplied `slug` wins. Otherwise the slug is the start date, the venue slug (or slugified name) and the first five words of the event name. Duplicates within an edition get `-2`, `-3`, and so on. Routes read the slug stamped by `mapEvents` and do not recompute it.

`hasProgram` defaults to `true` when absent.

## Previewing clock-sensitive and unpublished states

Some surfaces render only during the event window, or only when documents exist that the dataset does not have.

Clock: set `NEXT_PUBLIC_ZSB_TODAY=YYYY-MM-DD` in `.env.local` and restart the dev server. `todayInBucharest()` reads it for both the server clock (Latest and Upcoming split) and the client clock (event past-ness). A malformed value throws. The override is ignored when `NODE_ENV` is `production`, and a date passed explicitly (as tests do) takes precedence.

Content: author stand-in documents as drafts in the dataset and view them through draft mode. Requests outside draft mode use the `published` perspective, so drafts do not reach visitors. There is no fixture layer; fixtures would duplicate every mapped shape and fall outside TypeGen.

## Scripts

`scripts/sanity-upload-organization-logos.ts` uploads organization logos to the dataset. It runs with `pnpm exec tsx scripts/sanity-upload-organization-logos.ts`, loads `.env.local` through `scripts/_load-env.ts`, needs `SANITY_API_WRITE_TOKEN`, and writes to the dataset named in the environment. ## TypeGen

Run `pnpm typegen` after any schema or query change and commit `schema.json` and `sanity.types.ts`. CI regenerates `sanity.types.ts` and fails if it differs from the committed file.

## Adding a singleton page

The steps use a hypothetical `contactPage`.

1. Define the schema in `src/sanity/schemaTypes/documents/contactPage.ts` and register it in `schemaTypes/index.ts`.

   ```ts
   export const contactPage = defineType({
     name: 'contactPage',
     title: 'Contact',
     type: 'document',
     icon: EnvelopeIcon,
     fields: [
       defineField({ name: 'hero', type: 'pageHero', validation: (rule) => rule.required() }),
       defineField({
         name: 'body',
         type: 'array',
         of: [{ type: 'text', rows: 3 }],
         validation: (rule) => rule.required().min(1),
       }),
     ],
     preview: { prepare: () => ({ title: 'Contact' }) },
   })
   ```

2. Add `'contactPage'` to `SINGLETON_TYPES` and `singletonListItem(S, 'contactPage', 'Contact')` to `structure.ts`.

3. Add the query and its tags to `queries.ts`. The `defineQuery` result must be assigned to a variable so TypeGen finds it.

   ```ts
   const CONTACT_PAGE_QUERY = defineQuery(`*[_id == "contactPage"][0]{ hero, body }`)
   export const CONTACT_PAGE = { query: CONTACT_PAGE_QUERY, tags: ['contactPage'] }
   ```

4. Run `pnpm typegen`.

5. Write the fetcher. It keeps `'use cache'` and goes through `queryData`.

   ```ts
   export async function getContactPage(options: DynamicFetchOptions): Promise<ContactPage | null> {
     'use cache'
     return (await queryData(CONTACT_PAGE, options)) ?? null
   }
   ```

   Normalize in the fetcher or its mapper so the view-model is total: text becomes `''`, lists become `[]`, and only genuinely optional members stay absent. `getAboutPage` and `normalizeAbout` show the pattern.

6. Add a `defineLocations` entry for `contactPage` in `presentation.ts`.

7. Write a pure `ContactShell` that takes the view as props, register it in `PAGES` in `singleton-page.tsx` with `defineSingleton({ load, Shell, generateMetadata })`, and create `contact/page.tsx`:

   ```tsx
   const page = singletonPage('contact')
   export const generateMetadata = page.generateMetadata
   export default page.Route
   ```

   `load` returns `null` when the singleton is absent, which produces a 404. `editionsNav: true` appends the editions band.

8. Add the document type to the webhook filter at sanity.io/manage. Both the filter entry and the query's `tags` are required for publishes to invalidate the cache.
